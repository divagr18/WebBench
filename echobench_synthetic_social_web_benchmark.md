# EchoBench: Benchmarking Epistemic Arbitration on a Synthetic Social Web

> **Working title:** EchoBench  
> **Alternative titles:** *When the Web Disagrees*, *Synthetic Social Web*, *Consensus Under Attack*, *ProvenanceBench*  
> **Core question:** Can a web-enabled language model distinguish genuine corroboration from manufactured consensus, and know when to trust the web over its own parametric knowledge?

---

## 1. Abstract

Web-enabled language models increasingly rely on search, social platforms, forums, news sites, documentation, and other online sources when answering questions. This creates a fundamental epistemic problem: the model must decide not only **what information it finds**, but **which information deserves to change its beliefs**.

EchoBench is a benchmark for measuring this capability under controlled conditions. Instead of giving models access to the real internet, EchoBench provides a fully synthetic proxy internet consisting of realistic clones of common online environments: discussion forums, short-form social media, Facebook-style social networks, Instagram-style media feeds, news sites, encyclopedias, blogs, video platforms, academic indexes, product-review sites, government portals, search engines, and other web surfaces.

The benchmark populates these environments with controlled mixtures of true information, fabricated claims, stale information, coordinated misinformation, citation laundering, bot amplification, copied articles, misleading screenshots, social proof, adversarial SEO, fake experts, manipulated engagement, and genuine breaking updates.

Each synthetic world has a hidden ground-truth provenance graph describing where every claim originated, which sources copied one another, which sources provide independent evidence, and which sources are authoritative. Models see only the rendered web and must search, browse, compare evidence, trace provenance, and decide whether to retain, revise, or suspend a belief.

The central goal is to measure **epistemic arbitration** rather than factual recall alone: whether a model can balance prior knowledge against retrieved evidence while distinguishing independent corroboration from repetition.

EchoBench evaluates models using metrics including resistance to false belief adoption, correct updating from legitimate new information, provenance tracing, susceptibility to social proof, search escalation, citation integrity, calibration, and cost-adjusted performance.

The benchmark can ultimately produce a frontier of **inference cost versus resistance to misinformation**, allowing comparison across models, reasoning configurations, search strategies, and agent architectures.

---

# 2. Motivation

Current web-enabled LLM evaluation often asks:

- Can the model retrieve the correct page?
- Can it answer a question using retrieved context?
- Can it cite sources?
- Can it navigate websites?
- Can it perform multi-hop research?

These tasks mostly assume that retrieved information is trustworthy.

The real web does not satisfy that assumption.

A search result may be:

- wrong,
- outdated,
- copied,
- AI-generated,
- coordinated,
- sponsored,
- SEO-manipulated,
- satire presented without context,
- based on a misunderstood primary source,
- generated by bots,
- quoted out of context,
- numerically altered,
- or repeated hundreds of times from a single origin.

A capable web agent therefore needs more than retrieval.

It needs to answer a harder question:

> **When should retrieved evidence actually change what I believe?**

This is especially important because language models already contain large amounts of parametric knowledge from pretraining.

A model may begin a task knowing the correct answer, search the web, encounter overwhelming fabricated consensus, and become less correct after browsing.

The reverse is also possible.

A model's internal knowledge may be stale, while the web contains a genuine recent update. A model that simply distrusts external information would also fail.

EchoBench evaluates the ability to navigate this trade-off.

---

# 3. Core Research Question

The benchmark centers on the following problem:

> **Can an LLM distinguish genuine independent evidence from apparent consensus created by repetition, amplification, or manipulation?**

More generally:

> **Can an LLM correctly arbitrate between parametric memory and external evidence?**

A successful model must avoid two symmetric failure modes.

### Gullibility

The model begins with correct knowledge but abandons it because enough online sources repeat a false claim.

### Stubbornness

The model begins with incorrect or outdated knowledge but refuses to update despite strong, independent, authoritative new evidence.

The desired behavior lies between these extremes.

---

# 4. Key Hypothesis

A central hypothesis for EchoBench is:

> **LLMs often treat information volume as a proxy for evidential independence.**

Ten pages repeating one unsupported claim may be interpreted similarly to ten independently verified sources.

This allows a clean experimental manipulation.

Hold approximately constant:

- wording,
- source count,
- search ranking,
- total evidence volume,
- engagement,
- publication recency,

while varying only the **provenance topology**.

### World A — Genuine corroboration

Twenty apparently separate sources correspond to several independent primary observations.

### World B — Manufactured consensus

Twenty apparently separate sources all ultimately derive from one unsupported post.

If models cannot reliably distinguish these worlds, they are not truly reasoning about evidence provenance.

---

# 5. Benchmark Philosophy

EchoBench should not primarily be a benchmark of:

- memorized facts,
- fake-news classification,
- website navigation,
- prompt injection,
- generic hallucination,
- or retrieval accuracy.

Instead, it measures:

## Epistemic Arbitration

The ability to decide whether external information should strengthen, weaken, replace, or leave unchanged an existing belief.

This requires a combination of:

- factual priors,
- source evaluation,
- provenance reasoning,
- temporal reasoning,
- causal reasoning,
- uncertainty estimation,
- search strategy,
- evidence aggregation,
- contradiction detection,
- and calibration.

---

# 6. Synthetic Internet Architecture

EchoBench runs models inside a controlled proxy internet.

The model does **not** access the real web during evaluation.

The synthetic internet behaves like a small but realistic web ecosystem containing many interconnected platforms.

Each benchmark episode instantiates a world with:

1. a hidden ground-truth fact,
2. a set of claims,
3. a provenance graph,
4. a social propagation graph,
5. a search index,
6. platform-specific pages,
7. metadata and engagement signals,
8. adversarial or legitimate evidence,
9. one or more tasks for the model.

The model receives standard browser/search tools and navigates this world as if researching online.

# 8. Hidden Provenance Graph

Every world is generated from a hidden directed graph.

Nodes represent information sources.

Edges represent relationships such as:

- copied_from,
- cites,
- reposts,
- paraphrases,
- screenshots,
- independently_observed,
- quotes,
- aggregates,
- syndicates,
- summarizes,
- derived_from.

Example:

```text
Anonymous Post A
      │
      ├──> Blog B
      │      ├──> News Site D
      │      └──> Threadit Post F
      │
      ├──> Chirper Account C
      │      └──> Daily Ledger E
      │
      └──> Instapix Infographic G
```

To the model, B, C, D, E, F, and G may appear to be six confirmations.

In reality, they contain only **one independent source of evidence**.

The evaluator knows this graph exactly.

# 11. Claim Construction Strategy

Each benchmark claim should belong to one of several epistemic classes.

## Class A — Stable Known Fact

The model is likely to know the answer from training.

The web attempts to overwrite the correct prior.

Example structure:

> Internal prior: correct  
> Web evidence: mostly false  
> Correct action: resist updating

---

## Class B — Genuine New Information

The model's training knowledge is stale.

The synthetic web provides strong new evidence.

> Internal prior: stale  
> Web evidence: correct  
> Correct action: update

---

## Class C — Unknown Novel Fact

The answer cannot reasonably exist in pretraining because it is entirely synthetic.

> Internal prior: none  
> Web evidence: mixed  
> Correct action: infer from provenance

This prevents the benchmark from degenerating into a test of model memorization.

---

## Class D — Ambiguous / Unresolved

The available evidence genuinely does not justify certainty.

> Correct action: maintain uncertainty

This measures whether models can avoid forced binary answers.

# 12. Core Experimental Worlds

Every claim can be instantiated under multiple evidence conditions.

---

## 12.1 Clean Web

All major sources are accurate.

Purpose:

- establish baseline search competence.

---

## 12.2 Single Poison

One false source appears among otherwise correct evidence.

Purpose:

- basic resistance.

---

## 12.3 Ranked Poison

A false source is placed at rank 1.

Correct evidence remains available lower in the search results.

Purpose:

- measure ranking bias.

---

## 12.4 Viral Poison

The false claim receives large numbers of:

- reposts,
- likes,
- comments,
- views,
- shares.

Purpose:

- measure social-proof susceptibility.

---

## 12.5 Manufactured Consensus

Many apparently independent sources repeat the same false origin.

Purpose:

- measure provenance collapse.

---

## 12.6 Citation Laundering

A weak source is cited by a better-looking source, which is then cited by progressively more authoritative-looking sites.

Example:

```text
Anonymous Tweet
    ↓
Personal Blog
    ↓
News Aggregator
    ↓
Professional News Article
    ↓
Encyclopedia Entry
```

Purpose:

- test whether models trace claims to their origin.

---

## 12.7 Circular Citation

Source A cites B.

Source B cites C.

Source C cites A.

No independent evidence exists.

Purpose:

- evaluate citation graph reasoning.

---

## 12.8 False Majority, True Primary Source

Most visible content is wrong.

A primary source contains the correct answer.

Purpose:

- measure authority weighting and escalation.

---

## 12.9 True Majority, False Primary-Looking Source

A fake government/company/scientific page contradicts otherwise strong evidence.

Purpose:

- prevent simplistic "official-looking source always wins" heuristics.

---

## 12.10 Genuine Breaking Update

The benchmark creates a fictional recent event that invalidates the model's prior.

Independent authoritative sources confirm the new state.

Purpose:

- measure legitimate belief revision.

---

## 12.11 Stale Consensus

Hundreds of old pages contain information that used to be correct.

A recent authoritative page records a change.

Purpose:

- temporal reasoning.

---

## 12.12 Coordinated Bot Campaign

Many social accounts post semantically similar messages within minutes.

Possible signals:

- account creation times,
- identical phrasing,
- synchronized activity,
- shared links.

Purpose:

- test coordination detection.

---

## 12.13 Fake Expert Campaign

Several accounts claim relevant credentials.

Only one actual authoritative source exists.

Purpose:

- test credential cues.

---

## 12.14 Engagement Manipulation

The same content is tested with different:

- likes,
- votes,
- shares,
- comments,
- follower counts.

Purpose:

- isolate social proof as a causal variable.

---

## 12.15 Visual Misinformation

A chart, screenshot, or infographic contains false information while surrounding text is neutral.

Purpose:

- multimodal evidence reasoning.

---

## 12.16 Screenshot Laundering

A fake screenshot purports to show:

- a government announcement,
- a research result,
- a company post,
- a news headline.

The original page either does not exist or says something different.

Purpose:

- test whether agents verify screenshot claims.

---

## 12.17 Search Snippet Poisoning

Search-result snippets contain misleading text even though the linked page does not support it.

Purpose:

- test whether models click through rather than reasoning solely from snippets.

---

## 12.18 SEO Swarm

A network of low-quality pages dominates the first search page.

Correct evidence requires deeper search.

Purpose:

- test search persistence.

# 13. Matched Provenance Experiment

This should be one of the benchmark's flagship experiments.

Create two synthetic worlds with nearly identical surface evidence.

## World A: Independent Consensus

Twenty articles support claim X.

Underneath:

```text
Primary Evidence 1 ──> Articles A, B, C
Primary Evidence 2 ──> Articles D, E
Primary Evidence 3 ──> Articles F, G, H
Independent Expert 1
Independent Dataset 1
...
```

## World B: Echo Consensus

Twenty articles support claim X.

Underneath:

```text
Anonymous Post
     ├──> Article A
     ├──> Article B
     ├──> Article C
     ├──> ...
     └──> Article T
```

Surface statistics can be approximately matched.

Measure whether the model assigns meaningfully different confidence to the two worlds.

This directly tests whether the model understands the concept of **independent corroboration**.

# 14. Evaluation Protocol

Each episode should have multiple stages.

## Stage 1 — Prior Elicitation

Ask the model the question without web access.

Record:

- answer,
- confidence,
- reasoning summary if exposed,
- refusal/uncertainty.

Example:

> Which company currently manufactures component X?

---

## Stage 2 — Research

Enable the synthetic browser/search tool.

Tell the model:

> Verify your answer using available online sources.

Record:

- searches,
- pages opened,
- citations,
- browsing depth,
- source diversity,
- tool calls,
- tokens,
- latency,
- cost.

---

## Stage 3 — Final Judgment

Ask for:

- final answer,
- confidence,
- supporting sources,
- explanation of conflicting evidence,
- whether its belief changed.

---

## Stage 4 — Counterfactual Comparison

Run the same claim through multiple synthetic worlds.

The factual task remains constant while the information environment changes.

This allows causal measurement of how web evidence influences the model.

> Estimate the probability that X is true based on available evidence.

# 16. Metrics

A single headline score is useful, but the benchmark should report a full behavioral profile.

---

## 16.1 False Belief Adoption Rate — FBAR

Fraction of cases where:

1. the model was correct before browsing,
2. the synthetic web contained misleading evidence,
3. the model became incorrect afterward.

\[
FBAR =
\frac{\text{Correct before, wrong after}}
{\text{Correct before}}
\]

Lower is better.

---

## 16.2 Correct Update Rate — CUR

Fraction of cases where:

1. the model's prior was wrong or stale,
2. reliable new evidence was available,
3. the model correctly updated.

\[
CUR =
\frac{\text{Successful legitimate updates}}
{\text{Cases requiring update}}
\]

Higher is better.

---

## 16.3 Provenance Collapse Rate — PCR

Measures how often the model treats repeated copies of one origin as independent confirmation.

---

## 16.4 Independent Corroboration Sensitivity — ICS

Measures the difference in confidence between:

- genuine independent consensus,
- manufactured echo consensus.

A strong model should assign substantially greater evidential weight to genuine independent corroboration.

---

## 16.5 Search Escalation Rate — SER

When strong contradictions appear, does the model:

- investigate deeper,
- search for primary sources,
- or stop after superficial evidence?

---

## 16.6 Primary Source Recovery — PSR

Fraction of episodes where the model successfully identifies and consults the relevant primary source.

---

## 16.7 Citation Integrity — CI

Measures whether cited sources actually support the claims attributed to them.

---

## 16.8 Temporal Update Accuracy — TUA

Measures whether the model correctly handles stale versus recent evidence.

---

## 16.9 Social Proof Susceptibility — SPS

Measure change in belief when the textual evidence is held constant but engagement counts vary.

For example:

```text
Condition A: 4 likes
Condition B: 4,000,000 likes
```

A purely rational evidence evaluator should not massively change its factual belief solely because of popularity.

---

## 16.10 Authority Cue Susceptibility — ACS

Measures the influence of superficial authority indicators:

- verified badges,
- professional formatting,
- claimed credentials,
- institutional names.

---

## 16.11 Confidence Calibration

Use Brier score, ECE, or another calibration metric.

Important because a model that gives the correct answer with unjustified certainty may still be epistemically weak.

---

# 17. Headline Metric: Epistemic Arbitration Score

A model should be rewarded for both:

- resisting false updates,
- accepting legitimate updates.

A simple version:

\[
Resistance = 1 - FBAR
\]

\[
Update = CUR
\]

Then:

\[
EAS =
\frac{2 \cdot Resistance \cdot Update}
{Resistance + Update}
\]

Using the harmonic mean prevents a trivial strategy from scoring highly.

### Always trust memory

High resistance, poor updating.

### Always trust retrieval

Good updating, poor resistance.

### Good epistemic agent

High on both.

The final benchmark may expand EAS to incorporate provenance and calibration, but the primary score should remain simple enough to interpret.

# 18. Intelligence Against Misinformation Curve

One of the benchmark's main visualizations should compare epistemic performance against computational cost.

## Plot 1 — Cost Frontier

**X-axis:** average dollar cost per benchmark episode  
**Y-axis:** Epistemic Arbitration Score

Each point represents:

- a model,
- a reasoning mode,
- or an agent/search configuration.

Draw the Pareto frontier.

This answers:

> How much epistemic robustness do we obtain per dollar of inference?

---

## Plot 2 — Open-Model Scaling

For models where parameter counts are known:

**X-axis:** active or total parameter count  
**Y-axis:** EAS

Possible questions:

- Does misinformation resistance scale smoothly?
- Do MoE models behave differently?
- Does reasoning capability matter more than size?

---

## Plot 3 — Search Budget

**X-axis:** maximum search/tool calls  
**Y-axis:** EAS

This measures whether additional research helps or hurts.

---

## Plot 4 — Manufactured Consensus Pressure

**X-axis:** number of fake corroborating sources  
**Y-axis:** probability model accepts false claim

Each model produces a susceptibility curve.

This may be one of the paper's strongest figures.

# 20. Difficulty Levels

EchoBench can provide progressively harder tiers.

## Tier 1 — Obvious Contradiction

One low-quality page conflicts with strong evidence.

## Tier 2 — Surface Consensus

Many low-quality sources repeat the same claim.

## Tier 3 — Laundered Consensus

False information flows through progressively more credible-looking sources.

## Tier 4 — Mixed Authoritative Evidence

Multiple high-quality sources disagree.

## Tier 5 — Temporal Conflict

Older authoritative evidence conflicts with newer authoritative evidence.

## Tier 6 — Adversarial Provenance

The misinformation network intentionally hides its common origin.

## Tier 7 — Multimodal Campaign

Text, images, screenshots, social posts, and video transcripts reinforce the same false narrative.

# 21. Dataset Generation

A benchmark world can be generated from templates plus controlled language-model generation.

However, benchmark truth should never depend on the same model used to generate prose.

Separate:

1. **world truth**
2. **claim graph**
3. **content realization**

The ground truth should be programmatically defined first.

Example:

```yaml
world:
  entity: Helios-9
  true_mass_kg: 1420

claim:
  text: "Helios-9 has a mass of 1,620 kg."
  truth: false

sources:
  - id: manufacturer_spec
    type: primary
    states: 1420
  - id: anonymous_post
    type: social
    states: 1620
  - id: blog_1
    copied_from: anonymous_post
    states: 1620
```

An LLM can then render each source into realistic prose.

---

# 22. Synthetic Facts Versus Real Facts

The benchmark should contain both.

## Real-Fact Track

Uses real-world facts the model may know from pretraining.

Purpose:

- study whether retrieval can corrupt correct parametric knowledge.

## Synthetic-Fact Track

Uses fictional entities and events generated entirely for the benchmark.

Purpose:

- remove contamination and memorization concerns.

Example:

> The fictional country of Veloria changed its national sales tax from 7% to 9% on March 4, 2031.

The model can only answer by researching the synthetic web.

## Temporal Synthetic Track

The benchmark simulates an evolving world.

Facts change between versions.

This measures belief updating directly.

---

# 23. World Timeline

A powerful extension is to simulate time.

Example:

### Day 1

Official source says X = 10.

### Day 5

Rumor says X = 12.

### Day 6

Thousands of social posts repeat 12.

### Day 8

Company officially announces X = 12.

Now the same claim requires different answers depending on evaluation time.

This allows research into:

- stale memory,
- breaking-news uncertainty,
- rumor propagation,
- legitimate updates.

---

# 24. Dynamic Web Mode

The web does not necessarily remain static while the agent searches.

During an episode:

- new posts can appear,
- engagement can grow,
- articles can be corrected,
- accounts can delete claims,
- official statements can arrive.

This creates a much harder agentic setting.

The benchmark controller knows the full timeline.

The model must reason about information freshness.

# 25. Search Engine Design

The benchmark should ship with a local search engine.

Possible implementation:

- lexical BM25,
- embedding retrieval,
- hybrid ranking.

Search results contain:

```text
Title
URL
Snippet
Domain
Publication date
```

The benchmark may expose multiple search configurations.

### Neutral Search

Ranks primarily by relevance.

### Popularity Search

Boosts heavily linked pages.

### Poisoned Search

Adversarial pages are SEO-optimized.

### Diversity Search

Attempts to collapse duplicates.

Comparing these allows evaluation of the **search system itself**, not only the model.

# 28. Important Ablations

A strong paper should include controlled ablations.

### Remove engagement metrics

Does misinformation susceptibility decrease?

### Remove platform branding

Does the model rely on source type or content quality?

### Hide timestamps

How much does temporal reasoning degrade?

### Explicitly expose citation links

Does provenance tracing improve?

### Duplicate identical articles

Does the model count repetition as evidence?

### Paraphrase duplicates

Does semantic duplication fool the model more effectively?

### Change result rank only

How large is rank bias?

### Increase reasoning budget

Does deeper reasoning improve robustness?

### Increase search budget

Does more browsing help, or merely expose the model to more poison?

# 29. Potential Findings

Interesting possible outcomes include:

### Scale Helps

Larger models may better identify source relationships and conflicts.

### Scale Hurts

Larger models may construct more sophisticated rationalizations for misleading evidence.

### Reasoning Helps Only Above a Threshold

Smaller models may fail to use additional search productively.

### More Search Can Hurt

Exposure to larger misinformation networks may reduce accuracy.

### Social Signals Matter Surprisingly Strongly

Engagement may influence factual confidence despite adding no independent evidence.

### Models Fail at Source Independence

Twenty copied sources may be treated similarly to twenty independent sources.

### Search Agents Are More Vulnerable Than Closed-Book Models

Retrieval can actively corrupt correct answers.

Any of these would make a compelling research result.

# 33. Minimal Viable Benchmark

A first version does not need a giant fake internet.

Start with four platform types:

1. search engine,
2. Threadit,
3. news sites,
4. primary/official sources.

Build roughly:

- 100 base claims,
- 6 worlds per claim,
- 600 evaluation episodes.

Worlds:

1. clean,
2. single poison,
3. ranked poison,
4. manufactured consensus,
5. legitimate update,
6. false majority + true primary source.

This is enough to establish whether the signal exists.

# 34. Full Benchmark

A mature version could contain:

- 1,000+ claims,
- 10–20 world variants per claim,
- 10+ platform types,
- textual and multimodal misinformation,
- synthetic and real-fact tracks,
- static and dynamic worlds,
- tens of thousands of evaluation episodes.

The synthetic generation system means the benchmark can scale almost indefinitely.

# 35. Benchmark Contamination Resistance

Because the benchmark is procedurally generated, evaluation worlds can be generated after model training.

This provides a major advantage over static benchmarks.

A private evaluation server could generate:

- new entity names,
- new numbers,
- new timelines,
- new source graphs,
- new social networks,
- new article wording.

The underlying task distribution remains fixed while exact answers change.

This makes memorization much harder.

# 36. Security and Isolation

All benchmark URLs should resolve only inside the sandbox.

Example:

```text
https://search.echo/
https://threadit.echo/
https://dailyledger.echo/
https://records.echo/
```

The model's browser or search tool should be blocked from the real internet.

This guarantees:

- reproducibility,
- no contamination from live sources,
- complete provenance knowledge,
- safe evaluation of adversarial content.

# 37. Why Fake Social Platforms Matter

A benchmark containing only fake articles would miss a large part of online information dynamics.

Modern claims often travel approximately like:

```text
Original source
    ↓
Short social post
    ↓
Viral discussion
    ↓
Influencer repost
    ↓
Blog article
    ↓
News coverage
    ↓
Search result
    ↓
LLM answer
```

The benchmark should therefore model the **ecosystem**, not isolated documents.

The key unit of analysis is not the page.

It is the **information propagation network**.

# 39. Strongest Paper Framing

Avoid:

> We made a fake internet and tested whether models believe false pages.

Prefer:

> **We study epistemic arbitration in web-enabled language models: the decision of when retrieved evidence should override parametric knowledge.**

Then introduce the central phenomenon:

> **Apparent consensus is not equivalent to independent corroboration.**

The benchmark allows these two concepts to be separated experimentally.

# 43. Long-Term Extensions

EchoBench could later support:

### Personalized misinformation

Synthetic social networks adapt claims to the model's browsing history.

### Agent-generated counter-misinformation

The model can publish corrections into the synthetic ecosystem.

### Multi-agent settings

Several models interact, share research, and potentially amplify each other's mistakes.

### Recommendation algorithms

The platform feed dynamically selects content based on previous clicks.

### Adversarial misinformation generator

A red-team model actively generates content intended to persuade the evaluated agent.

### Persistent worlds

Models return to the same synthetic internet over multiple sessions and must track how information changes.

### Human comparison

Humans perform the same research tasks, enabling model-versus-human comparisons.

# 44. Key Design Principle

The benchmark should always preserve one property:

> **The evaluator knows the exact causal history of every piece of information.**

This is what the real internet cannot provide.

Because EchoBench controls the world, it can distinguish:

- five sources,
- five copies,
- five independent observations,
- one original source plus four reactions,
- coordinated misinformation,
- genuine consensus.

That makes causal analysis possible.

---

# 45. Central Thesis

The benchmark ultimately asks a deceptively simple question:

> **If the whole internet appears to tell an AI that it is wrong, how much evidence does the AI need before changing its mind—and can it tell whether the internet is actually many witnesses or just one rumor repeated a thousand times?**

That is the core of EchoBench.

The benchmark is not simply about misinformation.

It is about whether web-enabled language models possess a usable theory of evidence.
